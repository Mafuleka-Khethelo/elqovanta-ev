# Car-specific charging estimates

The 30 October update presents this calculator within **Elqovanta Charging Assistant**, adds a limited-time calculation, applies manager-reported per-port power where known, and supports explicit pre-target return-reminder consent. See [Charging Assistant](CHARGING_ASSISTANT.md). Charger ratings remain nullable; unknown power is never fabricated.

This update adds a calculation alongside the original saved model. It does not train, replace or change that model, its seven inputs, frozen history, threshold or evaluation.

Drivers save up to five cars on **My vehicles**, choose a default and select today's vehicle before charger search/detail planning. Selection is private and stored in PostgreSQL, so it survives refresh and sign-in. Vehicle deletion safely clears selection/default references; an existing default is a fallback. Current battery percentages belong to each charge, never a permanent vehicle specification.

The make/model combobox supports typing, a dropdown and keyboard selection. It contains common model-name suggestions, not a claim to list every EV. Any missing model/year/version can be entered manually. Four exact, year/market-labelled variants have manufacturer-sourced starting values: 2020 UK Volkswagen ID.3 Pro Performance/Pro S and 2019 US BMW i3/i3s 120 Ah. Source links appear while selecting them; battery details remain editable owner-confirmed inputs. No battery pack is guessed from a generic model name. BMW's inconsistent AC table is deliberately not used to prefill an AC limit. See the [Volkswagen specification guide](https://www.volkswagen.co.uk/idhub/content/dam/onehub_pkw/importers/gb/downloads/brochures/used-cars/id-3/id-3-brochure-pricelist-dec-20.pdf) and [BMW specification](https://www.press.bmwgroup.com/usa/article/detail/T0285420EN_US/the-new-2019-bmw-i3-120ah-and-i3s-120ah).

Before starting or joining a queue, the driver enters current/target percentages and an **assumed average power reaching the battery** in kW and calculates the duration. Capacity and known AC/DC vehicle limits come from the selected saved car. The estimate uses the smallest applicable limit: assumed average, vehicle limit and manager-reported selected-port power. Existing catalogue power is unknown until a manager records it; the form explicitly asks for an assumption rather than inferring power from Level 1/2 or inventing it. A preview's duration does not count down; its finish timestamp is labelled as assuming charging starts at the preview time. Later arrivals and waiting shift completion. The session clock and alerts start only after the driver confirms being plugged in and presses Start charging.

```
Energy needed (kWh) = usable capacity × (target % − current %) / 100
Time (hours) = energy needed / assumed average battery-delivered power
```

For example, 60 kWh, 40% to 80%, at an assumed average 12 kW reaching the battery gives 24 kWh and approximately two hours. Grid/nameplate power is not necessarily average battery-delivered power. Peak charging power should not be treated as a guaranteed average. This first version uses an explicit constant-average assumption, not an invented charging curve, calibrated uncertainty interval or learned charging-time model. Users can enter a newer battery reading and power assumption to recalculate from the server's current time. Reaching 100% can take longer as charging slows; drivers should follow their vehicle's guidance.

The server saves immutable calculation revisions with a single active revision per session, version checks, request keys and actual server timestamps. A preview creates no participation or scheduled alerts. Direct start attaches the checked inputs atomically, re-anchored to the actual server start time. Joining a queue saves private provisional inputs without starting a session or scheduling its alerts. At an offer, the driver confirms a fresh current percentage, reviews a new calculation and confirms being plugged in before accepting. Acceptance and estimate attachment are atomic; an invalid calculation rolls back acceptance. Dashboard offer actions lead to this review instead of bypassing it. Older open clients/API consumers may still omit an estimate for compatibility; older sessions without estimates keep working and may add one from My session. The new browser journey requires the reviewed plan before direct start or acceptance.

Battery/vehicle details and waiting drivers' provisional plans remain private; other participants see only anonymous estimated target times or a driver-reported finished state. A charger may have several connected sessions with different target times; missing estimates are explicitly counted rather than filled with invented waiting minutes. Changing today's car never rewrites an active session's saved calculation.

The existing durable worker checks active revisions and sends persistent **in-app** alerts about ten minutes before the estimated target and when the estimated time arrives. Recipients are the charging driver and drivers currently waiting/offered at that charger. Keys, worker locks and notification phase flags prevent duplicates; a ten-minute per-session/phase cooldown limits revised-reading spam. Revised or removed estimates, completed charging and unplugged sessions stop obsolete alerts. Late joins see the current shared summary rather than receiving a history of alerts.

Messages say **estimated target time**, not confirmed battery full. An 80% target is not a full battery. Driver-reported completion generates a separate queue update. Completion never releases an app slot or skips FIFO: the next offer follows an unplug report. Normal driver controls are Start, Report charging finished and Report unplugged. Pause/Resume buttons are removed. Historical pauses and intervals remain intact; deprecated compatibility endpoints support old clients and cancel an obsolete estimate if used. Manager station closure is separately labelled as coordination closed.

Free Render hosting can sleep. Notification schedules survive in Neon and overdue work is handled after waking, but exact-time background delivery is not guaranteed. There is no vehicle/charger telemetry, external push, SMS or email integration.

Technical basis: [US Department of Energy charging factors](https://afdc.energy.gov/fuels/electricity-stations?lv=true), [Tesla on charging slowing near full](https://www.tesla.com/support/charging/supercharging), [Render free-service behaviour](https://render.com/docs/free).
